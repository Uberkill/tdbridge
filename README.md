# TDBridge

A multiplayer live-control system for TouchDesigner. Players join via a public URL on their phone and control interactive visuals in real time — no app install required.

---

## How It Works

```
Phone (Browser) ──WebSocket──► Node.js relay ──OSC/UDP──► TouchDesigner
                                                          port 9000
TouchDesigner ──OSC/UDP──► Node.js relay ──Terminal display
              port 9001
```

- **Node.js** (`src/server/relay.ts`) runs an Express + WebSocket server on port **8080**
- **Cloudflared** tunnels port 8080 to a public HTTPS URL (no port forwarding needed)
- **TouchDesigner** and Node.js communicate exclusively over **OSC/UDP** — no HTTP, no shared memory
- Players join at `<public-url>?room=<ROOM_CODE>`, enter their name, and get a controller UI

## Quick Start

### Requirements
- Node.js 18+
- TouchDesigner 2025.32460+
- Windows (cloudflared.exe is bundled)

### Start the System

Double-click **`Start_System.bat`** — this does everything:
1. Installs npm packages (first run only)
2. Compiles TypeScript → JavaScript
3. Starts the Node.js relay server
4. Launches Cloudflared tunnel
5. Prints the terminal dashboard with public URL + QR code

### Open TouchDesigner

Open **`testing_final.toe`** — the project self-initializes on startup via `startup_init`.

## TouchDesigner Network Layout

Inside `testing_final.toe → /project1/tdbridge_test`, the network is organized into colour-coded zones:

| Zone | Contents |
|---|---|
| **OSC RECEIVE LAYER** | `bridge_osc_in` — passive UDP buffer (no callbacks, no cook loops) |
| **DATA PIPELINE** | `osc_processor` polls OSC buffer every frame; `bot_motion` animates demo fish |
| **PLAYER SPAWNING + CLONES** | `user_data` table, `select_active` filter, `replicator`, `player_master`, `item1…itemN` |
| **PHYSICS WORLD** | `physics_world` (Bullet solver), arena walls, `physics_toggle` |
| **RENDERING LAYER** | `all_players` compositor, overlays, `room_code_display` |
| **LEGACY / UNUSED** | Old `web_server` DAT and stale callbacks — do not delete, just ignore |

## OSC Message Reference

### Node.js → TouchDesigner (port 9000)

| Address | Value | Meaning |
|---|---|---|
| `/slot_N_active` | `1` or `0` | Player N joined / left |
| `/slot_N_name` | string | Player display name |
| `/slot_N_x` | float -1…1 | Joystick X axis |
| `/slot_N_y` | float -1…1 | Joystick Y axis |
| `/slot_N_action1` | float 0/1 | ROTATE button |
| `/slot_N_action2` | float 0/1 | PULSE COLOR button |
| `/slot_N_slider1` | float 0…1 | SPEED slider |
| `/slot_0_room_code` | string | Room code heartbeat |

### TouchDesigner → Node.js (port 9001)

| Address | Value | Meaning |
|---|---|---|
| `/td/fps` | float | Engine frame rate (sent every ~30 frames) |
| `/td/error` | string | Real errors only (cook loop noise filtered out) |

## Key Design Decisions

**Why no callbacks on `bridge_osc_in`?**
TouchDesigner's cook engine treats any DAT referenced inside an OSC-In callback as a dependency. Writing to *any* table from a callback — even a plain queue table — creates a cook dependency loop that disables the OSC receiver. The fix: `bridge_osc_in` is a passive buffer with no callbacks. `osc_processor` polls it every frame via `onFrameStart`, completely outside the OSC cook cycle.

**Why 100 pre-populated rows in `user_data`?**
The Replicator COMP only spawns clones for rows present in its template table. Pre-populating all 100 rows and filtering with `select_active` (rows where `name != ''`) means the replicator never needs to add rows mid-session — it only pulses to add/remove clones, which is much more stable.

**Why `op.store()` in the callback?**
Earlier versions used a Table DAT as a queue buffer. Even with no wired connections, TD tracks DAT references inside scripts as cook dependencies. `op.store()` / `op.fetch()` is pure Python memory — completely invisible to the cook engine.
